# VDP renderer (milestone 4)

Asked by the user to see the Sonic 1 client's progress as pictures (no third-party
emulator screenshots: our engine, our C). Branch `ccr-c03681be-48dioy`.

## 2026-11-28 — first version

- `src/render.c`: one active line at a time, called by `vdp_line` before the HINT check,
  so the engine (`vdp_frame`) and the oracle (its own line loop) both draw, and HINT
  handlers' changes (LZ's water palette) show from the next line. Mode 5: planes, window,
  sprites with their limits and X = 0 masking, priorities, backdrop, left column blank,
  display off; colours 3 bits per channel scaled to 0-255. Not yet: shadow / highlight,
  interlace, mode 4, the partial first column of two-cell vertical scroll.
- `nmd_framebuffer(&w, &h)` (public); `machine.c` presents it to the host.
- Cost: drawing every line made a 9000-frame hybrid run 8x slower (3.5 s -> 27 s), which
  would have slowed every check. `nmd_config.no_render` skips drawing; the suites and
  nmd-oracle always set it, the hybrid runners unless `--screenshot` is given. Plane
  drawing then fetched per cell instead of per pixel: 16 s with drawing, 3.2 s without.
- `harness/png.c`: PNG without zlib (stored deflate blocks). `--screenshot N:FILE.png`.
- `tests/test_render.c`: backdrop, tile pixel, H / V flip, palettes, plane / sprite
  priorities, the 21st sprite on a line, line scroll, the window, display off. 23/23.
- Sonic 1 client runs: Sega / title fade, GHZ with its title card, LZ above and below the
  water line, SBZ 1 / 2: as expected; the hybrid run with C and without C give
  byte-identical PNGs.

## 2026-11-28 — desktop host

- `host/sdl/sdl_host.c` (optional library `nmd_sdl`, built when CMake finds SDL2): window
  (scaled, resizable, F11 fullscreen), keyboard and the first game controller as pad 1,
  frame pacing at the video rate (performance counter, resynchronised when late), pause,
  fast forward. The engine stays platform-free: the host is only a `nmd_host` table.
- `harness/play.c`: `nmd_play_main()`, the hybrid runner with that host; `nmd-play` (no C).
- Checked here without a display (`SDL_VIDEODRIVER=dummy`): the Sonic 1 client's `s1-play`
  runs 600 frames in 10 s (60 Hz), quits cleanly. Keyboard / controller input could not be
  exercised in the container (no display, no input devices).

## 2026-11-28 — frame rate, VSync, region

- Frame rate measured twice a second: in the window title always, on the picture with F
  (3x5 font, drawn on a copy of the frame).
- VSync on by default (`--no-vsync`, V): it paces the game only when the display's refresh
  is within 1.5 % of the game's rate (60 Hz displays for NTSC); otherwise the clock paces
  and VSync only avoids tearing (a 144 Hz display does not speed the game up). Off while
  fast-forwarding.
- `--region jp|us|eu` (default us; `--pal` = eu): the version register (overseas bit,
  PAL bit) and the pacing (59.92 / 49.70 Hz). Before, s1-play ran as a Japanese NTSC
  console. Measured without a display: 300 frames in 5.0 s (jp, us), 6.0 s (eu).

## 2026-11-28 — HUD on Caps Lock

- The key F is gone: with Caps Lock on (its state, so the HUD follows the keyboard light)
  a HUD at the top right shows the frame rate, the region and the game's rate, VSync (and
  whether the clock paces instead), the display's refresh, pause / fast forward. 3x5 font
  for A-Z, 0-9 and a few signs, each glyph over a darkened box. Checked by drawing it over
  a GHZ frame into a PNG (no display here).

## 2026-11-28 — HD HUD, capacity

- The HUD is drawn after the picture, in window pixels (logical size off), with a 5x7 font
  scaled by the window height, over a translucent panel: sharp at any window size.
  Checked by rendering the window offscreen (dummy driver, software renderer) and reading
  it back to a PNG.
- Capacity: the engine's time per frame (from present's return to the next present:
  game C, original code on the oracle CPU, VDP lines and drawing), waits excluded; shown
  as "MAX n FPS (k x)" in the HUD and title, printed at exit. Sonic 1 (170 routines in C,
  the rest on Musashi) in this container: about 380 frames per second (6.4x of 59.92 Hz).

## 2026-11-28 — the HUD in Inter

- The user asked for an unpixelated TTF font (Inter). No new system dependency:
  `third_party/stb/stb_truetype.h` (v1.26, public domain / MIT) rasterises
  `third_party/inter/Inter-Medium.ttf` (Inter 4.1, OFL 1.1, unmodified, licence alongside;
  sources and hashes in `third_party/README.md`), embedded as a C array by
  `cmake/embed.cmake`. `host/sdl/hud_text.c`: ASCII packed into one alpha atlas per pixel
  size (2x horizontal oversampling), tabular digits, drawn with SDL_RenderCopyF in the
  draw colour. The HUD: label / value columns over a translucent panel, size 1/36 of the
  window height (at least 12 px). Checked offscreen (PNG); s1-play runs.

- The HUD panel has a fixed size now (the widest text each column can show; the status
  row always present): it no longer changes size with its content.
