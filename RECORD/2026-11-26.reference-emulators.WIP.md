# Reference emulators for the contract's hardware facts

## 2026-11-26 — decision (user agreed) and first tests

- Why: the oracle runs the original code on nativemd's own hardware model, so a mistake in
  that model passes every suite. The contract's *to verify* points need an outside
  reference. Plan before: test ROMs for a MiSTer or a console, run by the user. Decided:
  reference emulators, run by the agent directly (cheap, repeatable); the MiSTer stays for
  what the emulators cannot settle (they only say what their authors believed; an FPGA core
  is a reimplementation too; a console is the ground truth).
- Setup: `tools/refemu/fetch_cores.sh` (Genesis Plus GX @ 51348f65, BlastEm @ 1935a966, both
  libretro cores, fetched and built under work/, never committed), `refemu.c` (our libretro
  runner: N frames, no input, RAM dump in big-endian order, word order detected by the
  'NMDT' magic), `results.py` (compares result blocks), `run.sh` (all of it).
- Test ROMs in the `test-roms` repository (AS syntax, `build.sh`): a common frame
  (vectors, header, TMSS only when the version register asks for it, result block at
  $FF0000, green / red background) and four tests, one per *to verify* point: `romwrite`,
  `movel`, `tas`, `busword`.
- `movel` first used a VDP command whose halves in the other order make a read command; the
  control (halves by hand in the other order, then a data write) is an access nativemd
  rightly makes fatal (data-port write with a read code). Rewritten with two register writes
  to the auto-increment register in one MOVE.L: valid in either order, and the order decides
  where the next data word lands.
- Result: nativemd, Genesis Plus GX and BlastEm agree on every check, and with the contract
  (romwrite 6 checks, movel 7 with its control, tas 6, busword 5 with its control). The
  contract's four points now say *checked against reference emulators; to confirm on
  hardware*.

## 2026-11-26 — test ROMs moved to the client repository

- The user asked for the test ROM sources to live in nativemd-internal (`test-roms/`)
  instead of the `jgermade/test-roms` repository (which holds the game dumps in its
  releases). They are there now, with `build.sh` using that repository's toolchain and a
  `run.sh` that builds nmd-oracle and the cores into its `work/` and calls
  `tools/refemu/run.sh`. nativemd's docs and scripts no longer name a repository:
  `run.sh` takes any directory with a `build.sh`. Same results on all three machines.
