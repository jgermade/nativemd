# Oracle: frames runs resumed from a state (`--pc`)

## 2026-11-29 — Why and what

- Asked for by the Sonic 1 client's LZ object suites: several LZ objects (poles,
  harpoons, conveyors, invisible barriers) are not on any pad script's path. The client
  moves Sonic in a saved level state (`teleport.py`) and needs the oracle to continue the
  game from that state with real frame timing, capturing states at routine entries.
- Before: `--frames` always reset the CPU, and a `--state` given with it was silently
  ignored (the run booted from reset).
- Now: `nmd-oracle ROM --state S --pc ADDR --frames N` loads S, takes the registers from
  it and starts the CPU at ADDR (no reset). A state saved at the end of a frames run has
  no PC; there a game in sync waits in its idle loop, so ADDR is that loop (`--idle`'s
  start). `--state` without `--pc` in frames mode is now an error.
- `oracle_run_frames(frames, resume_pc)`: 0 keeps the reset. docs/harness.md updated.
- Checked with the client: LZ 1-3 states moved next to those objects resume, play on and
  give captured states of all four objects; their suites pass.
