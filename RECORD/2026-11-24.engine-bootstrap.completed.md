# Engine bootstrap

## 2026-11-24 — initial plan and first code

Context: the user supplied a plan (in Spanish) for a reusable native Mega Drive engine in
the style of nativeshvc. It is now in English in `ROADMAP/2026-11-24/`.

### Done

- `docs/contract.md` (draft 0.1), `docs/trace-format.md`, `docs/harness.md`.
- Public headers in `include/nativemd/`: `machine.h`, `z80.h`, `hw.h`, `cart.h`, `host.h`,
  `trace.h`, `nativemd.h`.
- Engine (`src/`): 68000 memory map, fatal errors, routine table dispatch, VDP ports,
  registers, VRAM/CRAM/VSRAM, instant DMA (68k, fill, copy), HINT line counter and VINT,
  3-button pad, Z80 RAM + BUSREQ/RESET + bank register + YM2612 register latch, ucontext
  coroutine scheduler, null host with scripted input, trace writer/parser, `.nmds` state files.
- Tools: `nmd-tracediff`, `mkhello` (generates our own `hello` ROM image).
- Tests (CTest, all green): `core` (unit tests), `hello` (end to end, 10 frames, headless),
  `hello_trace` (golden trace `tests/hello/hello.trace`, checked by hand before adopting).

### Decisions

- C11 + CMake. Single global machine (`m68k_rd16(addr)` takes no context).
- Game code runs in a coroutine; interrupts are taken only at wait points
  (`wait_vblank`, `wait_until`). Busy-waits on interrupt-driven state become `wait_until`.
- 32-bit = two 16-bit accesses, high word first; `m68k_wr32_predec` for `-(An)`.
- Odd 16/32-bit access, unmapped access, ROM write without a chip, Z80 space without
  BUSREQ: fatal.
- `TAS` does not write back (MD behaviour); to verify on the oracle.
- Trace comments (`#`) are ignored when comparing.

### Open questions

- License of the project (not chosen; no LICENSE file yet).
- Oracle: Musashi vs patched Genesis Plus GX; BlastEm bus tracing.
- Which disassemblies are complete and bit-perfect today.
- Verify: VRAM fill/copy byte order, word access to 8-bit devices, `MOVE.L` order per mode,
  Z80 access while in reset.
- `hello.bin` has placeholder 68000 code (`STOP #$2700`); a real 68000 version is needed for
  the oracle (needs an assembler choice).

### Decisions

- **License: MIT** (`LICENSE`, holder "jgermade"). Engine must not include GPL/AGPL or
  Genesis Plus GX (non-commercial) code.
- **Oracle: Musashi** (MIT), vendored in `third_party/musashi` at commit `313ebf1`, own
  `m68kconf.h`. The oracle runs the original code on Musashi with the **engine's own
  hardware model** behind it, so it verifies the CPU side (ASM vs C). Hardware is to be
  validated separately.
- **Assembler: vasm recommended**, but it could not be fetched here: the official site is
  unreachable from this environment, and building it from an unofficial GitHub mirror was
  blocked by the session's safety policy. Workaround: `tools/mkhello.c` encodes the
  `hello.s` instructions directly and the `hello_disasm` tests check the encoding against
  `tests/hello/hello.lst` with Musashi's disassembler. vasm stays the plan for larger test ROMs.
- Trace filters in the oracle: no instruction fetches, no interrupt vector fetch, no
  accesses to the stack range (default 1 KB below the initial SSP).
- Poll reads: `wait_until` reads and the oracle's `--idle` loop reads are collapsed the
  same way, so a busy-wait in ASM and its `wait_until` form give the same trace.

### Findings

- **Musashi omits the read cycle of `CLR` to memory.** The 68000 performs it, and the
  contract models it (`m68k_clr*`). The oracle adds it. Found by the first ASM-vs-C run.
- Behaviour that depends on instruction timing (e.g. a HINT latched while interrupts are
  masked during init, firing when SR is lowered) cannot be reproduced by the C model; the
  contract now says so. `hello` enables HINT from VINT to stay out of that case.
- Musashi fetches the next opcode after the instruction hook asks it to stop; the oracle's
  sentinel address reads as `NOP`.

## 2026-11-24 — harness for real clients: capture, suites, replay, hybrid

### Done

- **State files v2**: VDP/I/O/Z80 latches; `nmd_state_image` with capture/apply/read/write.
  v1 files still load. `nmd-statediff` now compares images (latches included).
- **Oracle as a library** (`harness/oracle/oracle.{h,c}`); `nmd-oracle` is a thin CLI.
  New: `--capture ADDR` saves states at a PC while the ROM runs.
- **Suite runner** (`harness/suite.{h,c}`): oracle and C in one process per state; trace +
  state comparison; `--regs`, `--ignore-ram`, `--replay`, `--keep`; fatal errors per state.
- **Side-effect read replay** in the engine (`nmd_replay_open`).
- **Hybrid execution**: engine hook `nmd_set_missing_routine_handler`; the oracle runs
  routines without C (C → ASM) and diverts into C when ASM reaches an address with C
  (ASM → C, returns as RTS); the declared idle loop yields to the engine's frame loop.
- hello: `ReadPad` moved to `$460` with a C ABI wrapper (`d0.b`); `Error` to `$4A0`.
  20 CTest tests green, including: suites for VInt/HInt/ReadPad on captured states, replay,
  a deliberately buggy C that the suite must reject, and hybrid runs (HInt only; HInt +
  ReadPad) whose trace and state equal the full-oracle run.

### Findings / decisions

- Musashi is not re-entrant: each nested oracle run saves and restores the CPU context, and
  per-action data (the parked PC) must be copied to locals before nested runs can happen.
  Bug found by the ASM → C hybrid test.
- The suite always skips the stack range (sentinel and exception frames differ by design).
- Lesson for the build checks: grepping build output for "error" missed `mkhello`'s
  overlap message; check the build's exit status.

  This needs VDP rendering only for visual checks; the harness works without it.

- Oracle frames mode: allowed far more video frames per VINT (Sonic masks VINT for ~60 frames

## 2026-11-24 — decision A on lag frames; first Sonic 1 routines in C

- **Decision (user agreed): lag frames stay outside the contract.** The oracle marks them
  (`# lag VINT n` in traces, summary on stderr: 2 in the first 300 frames of Sonic 1, 26 in
  1500); `nmd-tracediff` warns when a lag frame precedes a divergence. Full-run checks of C
  are made against hybrid runs. Future option noted: a per-routine cost model.
- `nmd_hybrid_main(argc, argv, game)` in the harness library, so a game's runner can pass
  its routine table; `nmd-hybrid` is the no-C case.
- `nmd-statefuzz`: sweep / random / fixed values for register parts and RAM; CTest
  `hello_fuzz` + `hello_suite_hint_fuzz` (22 tests green).
- **Sonic 1 client** (kept outside this repo; currently only in the session scratchpad):
  `RandomNumber`, `CalcSine`, `CalcAngle` in C. Results in `docs/sonic1.md`: all suites pass
  on captured, swept, random and edge states; hybrid with these in C equals hybrid without
  C over 3 368 172 accesses (1015 calls into C, 1500 frames).
- Findings: captured states can be very narrow (CalcSine: 2 angles in 1500 frames); random
  fuzzing missed an edge-only bug that hand-picked edge cases caught; equivalent mutations
  exist and are not harness failures.
- Open: where the Sonic 1 C lives (a separate private repository; it must not go into the
  MIT engine repository).

## 2026-11-25 — harness changes driven by the Sonic 1 client

- The Sonic 1 C now lives in a separate private repository (with nativemd as a submodule);
  this repository stays free of game code.
- `nmd-statefuzz`: `(aN+OFF)` RAM fields and `LO-HI:STEP` ranges (`3f71433`).
- `nmd-oracle --capture-every K` (`a6e2947`): `--capture-max` alone keeps only the first
  calls, which cluster at the start of a level.
- Lessons from the client: captured states can be narrow; random fuzzing misses rare paths;
  hand-written edge states (including synthetic data written into RAM, e.g. animation
  scripts) catch bugs that real and random states do not. Real gameplay needs a pad script
  (the attract-mode demos do not reach many routines).

## 2026-11-25 — oracle stack filter was too wide (fixed in d2c26ef)

- The default "stack" filter (1 KB below the initial SSP) dropped real data accesses on
  Sonic 1, whose stack is $140 bytes with variables right below it; comparisons also ignored
  that RAM. Now: accesses between the current A7 and the SSP (allowing for pops raising A7
  before reading and MOVEM -(A7) writing before lowering it); suites ignore only the RAM the
  oracle used as stack in that run. Lesson: harness defaults that hide data need a test
  that proves they hide only what they should.
