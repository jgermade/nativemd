# ROM writes without a mapper: ignore, trace and report

Decision record; implementation planned for the start of the next session.

## 2026-11-25 — decision (user agreed)

Context: Sonic 1's SolidObject (FixBugs = 0) writes `move.w #id_Run,obAnim(a1)` with a1 = the
object's code address when an object is off screen with its pushing bit set: a 16-bit
write into ROM. Today `src/bus.c` makes any ROM write that no mapper claims fatal
(contract section 3: "the engine never silently ignores an access the game should not
make"), so runs stop and the client had to stop generating such states (Springs).

Decision, chosen for debugging:

1. **Effect**: none. ROM is unchanged, as on hardware without a mapper (believed; to verify
   with a test ROM on a MiSTer or a console).
2. **Trace**: the write is always traced as an ordinary access, so suites and hybrid
   comparisons still check that the C makes exactly the same write (address, value, order)
   as the original; a ROM write only one side makes is a divergence at its exact position.
3. **Report**: a summary at the end of a run (count, grouped by address, with the PC of the
   first write to each), so it is visible without flooding the output. Not silent.
4. **Strict mode**: an option (`--rom-writes=fatal` on the tools, and a config field for
   hosts) restores today's fatal error, with the PC and registers, for chasing corrupt
   pointers.
5. **Mappers**: a cartridge connector that claims the address (SRAM / bank registers) gets
   the write as now; only unclaimed ROM writes are ignored and reported.
6. Unmapped addresses and Z80 space without BUSREQ stay fatal.

Implementation plan (next session):

- `src/bus.c`: ROM writes without a mapper → trace, count per address (first PC), ignore;
  fatal only in strict mode. Where the oracle (Musashi) writes, the same path.
- A config field in `nmd_config` and `--rom-writes=ignore|fatal` in nmd-oracle, the suite and
  nmd-hybrid; end-of-run report in those tools.
- `docs/contract.md` section 3: replace "writes to ROM without a mapper chip: fatal" with the
  rule above, marked *(to verify)* on hardware; `docs/harness.md`: the option and report.
- A unit test: a ROM write is ignored, traced and counted; strict mode makes it fatal.
- Client (nativemd-internal): re-enable the off-screen + pushing case in the Springs edge
  generator (and the other grids around objects), and check the hybrid comparisons still
  match with the writes traced on both sides.
