# Delta state files (NMDD)

## 2026-11-30 — Why and what

- The Sonic 1 client's check.sh derives ~300 000 fuzzed and edge states from its captures
  (~41 GB at ~140 KB each, ~58 GB with the captures) and the disk is the limit for more
  zones. A fuzzed state differs from its base in a few bytes.
- New file kind `NMDD`: the absolute path of a plain (NMDS) base file and the patches
  (offset, length, bytes) that turn its bytes into the state's. `nmd_state_read` resolves
  it transparently (the file is read into memory, a delta is expanded against its base,
  then parsed with `fmemopen`), so `nmd_state_load`, the suites, the oracle and
  nmd-statediff read both kinds unchanged.
- `nmd_state_write_delta(path, base, image)`: runs of changed bytes, merged through gaps
  of up to 8 equal bytes; a full file when the base is not a plain one.
  `nmd-statefuzz --delta`. A typical fuzzed state: 81 bytes.
- test_core: delta round trip (image equality, load and apply). All 23 tests pass.
- A first version looped forever: a run that ended on 8 equal bytes stopped one byte
  short and restarted at the same byte. Runs now end after the last differing byte.
